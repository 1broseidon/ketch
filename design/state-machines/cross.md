# search, code, and cross-cutting state

## Summary
Eight implicit machines; 1 MUST, 5 SHOULD, 2 COULD. The worst is the exit-code / error-kind classifier: ADR-0002 says CLI and MCP "derive from one internal classification", but there are two hand-mirrored switch statements plus four mirrored per-command pairs, and they already disagree on timeouts (MCP `[cancelled]`, CLI exit 4) — two providers in the tree encode opposite workarounds for that disagreement (search/exa.go:190-199 keeps the `DeadlineExceeded` chain "for CLI/MCP classification"; docs/web.go:665-676 strips it because "[cancelled] over MCP while the CLI exits 4"). The upcoming refusal lifecycle has no category in this taxonomy and will be classified wherever the first caller decides. Second worst: the auto chain treats every provider error as "fall through" with no reason, has no memory of a rate-limited provider even within one MCP process, and doctor counts a rate-limited provider as `ok`, so doctor says "ddg serving, 3 of 3 healthy" on an install where every search exits 4. Descendants of the three prior bugs are recorded under machines 1 (chain re-spends a dead provider's timeout per call), 4 (one classification per surface), 5 (empty result conflated with absence) and 8 (failure backoff that persists only if a cache already existed).

## Machines

### Exit-code / error-kind classification — MUST
- Where: cmd/exit.go:42-69 (`backendErr`, `upstreamErr`); mcp/errors.go:56-78 (`upstreamErrf`, `backendErrf`); main.go:26-36 (cancellation checked only for `context.Canceled`); mirrored pairs cmd/code.go:89-100 ↔ mcp/code.go:92-100, cmd/scrape.go:350-361 ↔ mcp/scrape.go:181-191, cmd/scrape.go:390-400 ↔ mcp/scrape.go:196-205, cmd/tag.go:135/165/208/245 ↔ mcp/tag.go:102/121/130/150; direct `exitErrf(ExitUpstream, …)` bypassing `upstreamErr` at cmd/search.go:81,279,335; cmd/cache.go:142; cmd/doctor.go:57.
- States: a terminal failure is in exactly one of {validation, not_found, upstream, precondition, cancelled} (ADR-0002, design/adr/0002-error-code-taxonomy.md).
- Transitions: decided by `errors.Is` against package sentinels (docs.ErrNotFound, docs.ErrLibraryRequired, code.ErrRepoNotFound, code.ErrRegexpUnsupported, scrape.ErrInvalidURL/ErrNoBrowser/ErrBadSelector/ErrSelectorNoMatch, extract.ErrPDFNoText, bolterrors.ErrTimeout) at each surface independently. Cancellation: CLI = `errors.Is(err, context.Canceled)` in main.go:29 only; MCP = `Canceled || DeadlineExceeded` in mcp/errors.go:59.
- Today: two parallel implementations kept in step by comments ("the same rule the CLI applies in cmd's upstreamErr", mcp/errors.go:55; "Mirrors the MCP code tool's [validation] classification", cmd/code.go:94). No shared type; no parity test (cmd/exit_test.go has one case, mcp/errors_test.go one; no test asserts cmd and mcp agree).
- Risk: (1) Timeouts diverge today. Providers wrap transport errors with `%w` (search/brave.go:109, search/ddg.go:80, search/searxng.go:64, search/keenable.go:153), so a per-backend `context.WithTimeout` deadline (search/auto.go:228, multi.go:171, random.go:64) or the client timeout (httpx/client.go:16, 30s) reaches the surface as `DeadlineExceeded` on a single-backend call: MCP says `[cancelled]` ("you cancelled"), CLI exits 4 ("retry"). docs/web.go:665-676 already works around this per-caller; search/exa.go:190-199 does the opposite on purpose. (2) `bolterrors.ErrTimeout` ("busy, try again") is classified precondition (cmd/cache.go:142, cmd/tag.go:135) — ADR-0002 says precondition means "operator must configure", retry is 4. (3) doctor maps `unreachable` (network) to exit 5 (cmd/doctor.go:56-58; documented at cmd/doctor.go:26-30 but contradicts the taxonomy). (4) The planned refusal floor has no category: `not_found` is "resource absent", `validation` is "fix input"; a below-floor refusal with reasons per stage (local/web/Context7) will be mapped by whichever call site lands first, once per surface.
- Explicit form: one package (e.g. `internal/failure`) with `type Kind int` {Validation, NotFound, Upstream, Precondition, Cancelled} and `type Classified struct { Kind; Reason string; Err error }`; a single `Classify(err) Classified` owning every sentinel check and the cancellation rule (Canceled → Cancelled; a deadline that is not the caller's → Upstream with Reason "timeout"); cmd maps Kind→exit code, mcp maps Kind→prefix. Providers wrap a `failure.ErrTimeout` sentinel rather than re-exporting `context.DeadlineExceeded`. Refusal becomes `Kind: NotFound, Reason: "below_floor"` (or a new kind) decided once.
- Agent-visible: a stable reason after the kind, `[upstream:rate_limited]`, `[not_found:below_floor]`, and a `reason` field in MCP structured output; CLI `--json` error envelope with `{kind, reason}`.

### Auto fallback chain — SHOULD
- Where: search/auto.go:61-78 (`autoChain`: eligibility + promotion sort), 85-97 (`orderedChain`), 131-133 (`autoPromoted`), 158-184 (`NewAutoFromConfig`; 170-173 silently drops a provider whose `New` fails), 209-241 (`SearchSelect`), 246-258 (`stop`); search/registry.go:52-57 (`InAuto`); consumers cmd/search.go:197-208 and 73-85, mcp/search.go:93-108; search/random.go:46-77 (same loop, no total budget).
- States: per provider in a chain run: not_eligible (InAuto false) | dropped_at_build (auto.go:172) | untried | failed(reason) | served; per chain: running | stopped_cancelled | stopped_budget | exhausted.
- Transitions: eligibility by `AutoRank != 0 && !Hidden && Usable && AutoEligible` (registry.go:53-56); order by `Configured || AutoEligible` then rank (auto.go:71-76); attempt → served on `err == nil` (auto.go:231, including zero results, by design 204-208); any non-nil error → next provider (auto.go:234) with no classification; stop by `ctx.Err()` vs `chainCtx.Err()` (auto.go:246-258).
- Today: ordered `[]namedSearcher` + `err == nil`; failures carried as `BackendError{Backend string, Err error}` (multi.go:42-45) whose reason is free text per provider (brave.go:71-78, keenable.go:106-112, ddg.go:87-91). The chain never asks *why* a provider failed.
- Risk: (a) A permanent failure (401 "invalid API key", http_headers rejected) and a transient one (429, timeout) take the same transition, so "all 3 backends failed" is always exit 4 / `[upstream]` even when the honest class is precondition. (b) No memory: a rate-limited or hanging head-of-chain provider is retried on every call, including inside one long-lived MCP server; DDG alone spends 3 attempts + 1s of sleeps (ddg.go:71-91), and two 10s timeouts consume 20s of the 30s budget before a working third provider is reached (auto.go:23, 228). This is the "spent-quota short-circuit lived in one process but not the next" bug class, except here it does not live in *any* process. (c) `NewAutoFromConfig` drops a provider silently (auto.go:172 `continue`), so doctor's chain (`AutoChainNames`, doctor.go:162) and the runtime chain can differ with nothing reported. (d) CLI `--json` emits a bare results array (cmd/search.go:106-108): the serving backend and the fall-through failures are stderr-only there, while MCP has `backend` and `errors` (mcp/search.go:36-41). (e) Random duplicates the loop without the total budget (random.go:46-77): worst case N×10s vs Auto's 30s.
- Explicit form: `type Attempt struct { Backend string; Outcome: Served|Failed|Skipped|Ineligible; Reason: RateLimited|AuthRejected|Unreachable|Timeout|BadResponse|Other; Err error }` and `type Selection struct { Served string; Attempts []Attempt; StoppedBy: None|Cancelled|Budget }`; one `classifyProviderError(err) Reason` shared by Auto/Random/Multi and by the providers' own error constructors; an optional process-lifetime `cooldown map[backend]time.Time` set on RateLimited, consulted before each attempt.
- Agent-visible: `attempts: [{backend, outcome, reason}]`, `stopped_by`, and the same fields in CLI `--json` as an envelope or on stderr as JSON; `[precondition]` instead of `[upstream]` when every attempt was AuthRejected.

### Per-key rotation state — SHOULD
- Where: search/keys.go:11-66 (`keyPool`, `pick`, `pickDifferent`); search/brave.go:55-78, keenable.go:90-113, exa.go:145, parallel.go:210, tinyfish.go:45, firecrawl.go:136, serply.go:128, tavily.go:156, youcom.go:259 (retry predicate per provider); health/health.go:34-85 (`ProbeKeyPool`, pool status = worst key by priority 103-118); internal/configbase/config.go:45-61 (`MergeKeys`), settings.go:92-105 (env replaces the whole pool).
- States per key: unknown | accepted | rejected (401/402/403) | throttled (429). None stored anywhere at runtime.
- Transitions: pick uniformly at random (keys.go:36-41); on a credential status with pool size > 1, pick a different key once (brave.go:60-67); then classify the *second* response only (brave.go:70-75). Doctor probes every key concurrently and reports the pool's worst status (health.go:54-59).
- Today: stateless randomness + one retry; which statuses count as "credential" differs per provider (401|429 for brave/keenable/exa/parallel; +403 for tinyfish/serpbase/serply; +402 for firecrawl) — a predicate repeated at nine sites.
- Risk: a revoked key stays in the pool forever, costing an extra round trip on 1/n of calls, and the error after a double failure names only the second key (brave.go:71-75; test `TestBrave401ReportsOrdinalWithoutKeyValue`), so the revoked key is never identified outside doctor. Doctor collapses "one bad key of two" to `misconfigured` (health.go:54-59, 103-118) and exits 5 for an install whose searches succeed by rotation. Permanent (401) and transient (429) rejections take the identical transition.
- Explicit form: `keyPool` holding `[]keyState{key, state, until}` with `pick()` skipping rejected keys and throttled ones until `until`; `markRejected/markThrottled(key, status)`; one shared `isCredentialStatus(provider, code) (bool, reason)` table; `ProbeKeyPool` returning per-key outcomes and a pool verdict of ok|degraded|misconfigured.
- Agent-visible: error text / MCP `errors[backend]` naming every key tried and why; doctor detail "key 1 of 2 rejected, key 2 accepted" with status `degraded` rather than `misconfigured`.

### Doctor status enum vs provider reality — SHOULD
- Where: health/health.go:15-32 (enum), 103-118 (priority); per-provider probe mappings search/brave.go:146-155, ddg.go:113-120, keenable.go:190-199, exa.go:309, parallel.go:297, serpbase.go:246, serply.go:174, tavily.go:193, tinyfish.go:134, youcom.go:343, firecrawl.go:252 (429 → `ok`), searxng.go:113-130 and degoog.go:131 (429 → `misconfigured`); doctor/doctor.go:183-206 (`summarizeAutoChain`, only `StatusOK` counts), 157-169 (`withAutoChainCheck`), 113-150 (`withDocsAutoCheck`, chain order hardcoded at 114); cmd/doctor.go:56-58, 62-71 (exit 5 on any Required+Bad).
- States: the enum is explicit ({ok, no_key, unreachable, misconfigured, skipped}) but "answered 429 / rate limited" has no state; it lives in the `Detail` string.
- Transitions: each probe decides by HTTP status, inconsistently across providers for the same condition (429); the auto summary derives from member statuses.
- Today: a string enum plus free-text detail; the auto summary treats `ok`-with-"rate limited" detail as a serving provider.
- Risk: a chain whose every member is throttled reports `ok` "ddg serving, 3 of 3 providers healthy" (doctor.go:204) and doctor exits 0 while `ketch search` exits 4 on every call. SearXNG/degoog report the same condition as `misconfigured` → exit 5. Doctor's exit code conflates unreachable (network) with precondition. The docs chain order is encoded twice (doctor.go:114 and the docs package) and can drift.
- Explicit form: add `StatusDegraded` (or a `Reason` on `Check`: rate_limited|auth_rejected|timeout|bad_response|no_key) set by one `classifyProbe(resp, err) (Status, Reason)` used by all probes; `summarizeAutoChain` counts degraded members separately ("2 throttled, 1 healthy"); doctor exit code chosen from the worst Reason (unreachable → 4, config → 5).
- Agent-visible: `ketch doctor --json` `status: degraded, reason: rate_limited`; auto row `healthy: 1, throttled: 2`.

### Repo-scoped code search: empty vs absent — SHOULD
- Where: code/filter.go:66-70 (`MayLackRepo` = `PartialIndex && Repo != "" && len(results)==0`); code/sourcegraph.go:137-178 (alert "No repositories found" → `ErrRepoNotFound` only if `repo != "" && len(results)==0` *at the moment the alert event arrives*, line 167); code/github.go:159-165 (422 body substring `githubUnsearchable` → `ErrRepoNotFound`); code/grepapp.go:80-139 (no signal; repo filter narrowed client-side at 132); consumers cmd/code.go:89-115, mcp/code.go:92-122; cmd/exit.go:65 and mcp/errors.go:63 map `ErrRepoNotFound` → not_found.
- States for a repo-scoped query: has_results | empty_repo_present | empty_repo_absent (hard, exit 3) | empty_repo_unknown (grepapp, warning, exit 0).
- Transitions: decided by three different signals in three backends, one of them order-dependent on an SSE stream, one a boolean conjunction evaluated after the fact.
- Today: a sentinel error (explicit, good) for two backends and a three-boolean predicate for the third; the warning and the error both carry `not_found` (mcp/code.go:118 `warnf(kindNotFound…)` vs `[not_found]` error).
- Risk: the "search hit's failure counted as a package's failure" class inverted — an empty result read as absence, or absence read as "no matches". On Sourcegraph a `matches` event before the `alert` flips the outcome from absent to empty (sourcegraph.go:160-169). An agent sees `[not_found]` in `warnings` (soft: try another backend) and `[not_found]` as the error (hard) and cannot tell them apart by prefix.
- Explicit form: `Query` result carrying `RepoStatus: Present|Absent|Unknown` set by each backend, with `MayLackRepo` deleted; the CLI/MCP decide exit/warning from the enum.
- Agent-visible: `repo_status` in `ketch code --json` / MCP output; `[not_found:repo_absent]` vs `[not_found:repo_unindexed]`.

### Config load: display-only defaults and best-effort config — COULD
- Where: config/config.go:70-95 (`LoadFile`: on decode error returns `Defaults()` "for display only; nothing should act on it"), 150-160 (`Load`: env overlaid even on a failed file, invalid `http_headers` dropped); cmd/root.go:21-34 (`cfgErr` held, surfaced in `PersistentPreRunE`), 61-82 (`commandUsesConfig`, a name switch); config/env.go:176-193 (`applyEnv`: valid vars applied, invalid skipped).
- States: ok | file_unreadable (cfg = defaults, must not act) | env_partial (best-effort) | headers_dropped.
- Transitions: decided in `Load`, encoded as `(Config, error)` where the error's presence changes what the struct means.
- Today: the same `Config` value means "effective config" or "placeholder for flag defaults" depending on an error held elsewhere; the guard is a command-name allowlist.
- Risk: low — the allowlist defaults to "uses config", so a new command is safe by default. Env-over-file precedence for key pools is explicit (settings.go:93-104 replaces singular and plural together).
- Explicit form: `LoadResult{Config, Provenance: Effective|DisplayOnly, Problems []error}`; commands assert `Effective`.
- Agent-visible: `ketch config --json` already reports overrides; add `provenance`.

### Tag entry lifecycle — COULD
- Where: cache/tags.go:229-236 (`TagURL`: bare vs with-page entry), tag_store.go:67-110 (`PutTagEntry` fills empty title/description from the previous entry), 193-245 (`Backfill`: 100ms lock budget, `ErrTimeout` swallowed at 212-214 and 241-243), tags.go:296-330 and 393-440 (warmth computed at view time), 441-465 (`tagPageReader` status strings "available"/"unavailable"); cache/boltfile.go:41-82 (ADR-0006 open-per-operation, explicit and shared).
- States per entry: absent | tagged_bare (Title=="" && Description=="") | tagged_with_metadata; plus warm|cold computed per view.
- Transitions: `TagURL`/`TagResult` create; `fillTagMetadata` (tag_store.go:103-110) treats "" as "not yet"; `Backfill` writes only existing memberships (read then write in two separate opens, 210-220 — safe because it only updates).
- Today: empty-string sentinel for "unfilled"; two lock budgets chosen by call site (1s vs 100ms, documented constants); `CacheStatus` is a string.
- Risk: tidiness only. Open-per-operation is already explicit in `boltTx`; the lifecycle has no known bug.
- Explicit form: `TagEntry.Metadata: Unfilled|Derived|Supplied`; `CacheStatus` as a typed enum.
- Agent-visible: `cache_status` already exists; `metadata_source` would say why a title is blank.

### Update-check cache state — SHOULD
- Where: updatecheck/updatecheck.go:95-168 (`GetStatus`), 170-188 (`ShouldNotify`, re-reads state), 190-208 (`MarkNotified`, re-reads state), 275-287 (`isCacheStale`, `inFailureBackoff`); cmd/update.go:28-45 (400ms network budget on every interactive command).
- States: disabled | unversioned_dev | no_cache | cache_fresh | cache_stale | stale_in_backoff | live_ok | live_failed.
- Transitions: `hasCache` bool × `isCacheStale` × `inFailureBackoff` × `AllowNetwork` in `GetStatus`; `Source` string "none|cache|live" is the only trace.
- Today: four booleans and a string; state read from disk three times per command by three functions.
- Risk: a fetch failure with no existing cache persists nothing (137-145), so no backoff is recorded and every interactive command spends the 400ms network attempt until one succeeds — a stop condition that exists in the process that failed but not the next. Low stakes (TTY-only, stderr), but it is the "spent quota short-circuit lived in one process but not the next" pattern.
- Explicit form: `type phase int` derived once by `classify(state, now, opts) phase`; `GetStatus` switches on it; failures always write `LastCheckFailedAt`.
- Agent-visible: none required (notice is suppressed under `--json`, cmd/update.go:77-79).

## Already explicit
- health.Status (health/health.go:15-32): a real string enum with documented meanings and a priority order; the gap is a missing state, not an implicit one (see machine 4).
- Auto.stop (search/auto.go:246-258): cancellation vs budget is distinguished by which context expired and tested (`TestAutoSearchDistinguishesCancellationFromBudget`, auto_test.go:337-353).
- Multi (search/multi.go:160-197): per-backend `outcome{results, err}` collected after fan-out; "all failed" wraps `ctx.Err()` only when the parent was cancelled; empty success is not failure (tested).
- search_order validation (search/auto.go:104-125): invalid lists rejected with the valid names, never silently fixed.
- GitHub token resolution (internal/configbase/config.go:97-128): an ordered chain returning a typed-ish `source` of config|env|gh-cli|none, memoised with failures cached (130-170). `Usable` re-runs it (code/github.go:319) and `Search` re-checks `token == ""` (github.go:76) — a duplicated gate, not a state bug.
- Code sentinels (code/code.go:37-46): `ErrRegexpUnsupported`, `ErrInvalidRepo`, `ErrRepoNotFound` are typed and detected inside the package, as ADR-0002 wants.
- Page cache / tag index open-per-operation (cache/boltfile.go:41-82): ADR-0006 is implemented in one helper with an in-process RW lock; no handle lifetime to get wrong.
- Key pool merging (internal/configbase/config.go:45-61; settings.go:58-70, 92-105): env replaces file atomically; `Configured` is a single predicate.

## Cross-area edges
- search.Auto.SearchSelect → cmd/search.go:204 (stderr `warn:` lines, nothing under `--json`) and mcp/search.go:98 (`backend`, `errors` map): the chain hands `[]BackendError` to both surfaces, which render it differently; machine 2's `Attempt` would replace both.
- search provider `Probe` → health.ProbeKeyPool → doctor.buildSpecs (doctor.go:212-235) → cmd/doctor.go:56 exit 5: the pool's worst-status verdict and the `Required` predicate (registry.go:61-63) decide the exit code together.
- doctor.withDocsAutoCheck (doctor.go:113-150) hardcodes the docs chain `web → context7` and reads docs provider checks; the Context7 keyless-quota file described in CHANGELOG.md:12 (docs area) is the sibling of machine 2's missing cooldown — docs persists a "quota spent" short-circuit across processes, search persists nothing.
- cmd/exit.go:60-69 and mcp/errors.go:56-67 import docs.ErrNotFound / docs.ErrLibraryRequired / code.ErrRepoNotFound; cmd/scrape.go:350-361 and mcp/scrape.go:181-191 import scrape/extract sentinels. Any new refusal sentinel in docs must be added to both switches or both surfaces drift (machine 1).
- docs/web.go:665-676 (`callErr`) already strips `DeadlineExceeded` to avoid the CLI/MCP timeout divergence; search/exa.go:190-199 preserves it for the same stated reason. The shared classifier in machine 1 would retire both.
- config.Load (config/config.go:150-160) → cmd/root.go:21 `cfg` and → mcp via cmd/mcp.go:31: a `DisplayOnly` config reaching the MCP server would be guarded only by `commandUsesConfig` (`mcp` is not in the exemption list, so it is blocked — correct, by default).
- cache.Backfill (cache/tags.go:467-486 → tag_store.go:209-245) runs on every page-cache Put from the scrape path; its swallowed lock timeouts are the only place a tag write silently does nothing.
