# fetching

## Summary
Eight implicit machines in scrape/, crawl/, cache/, internal/docsfetch/ and httpx/: 1 MUST, 6 SHOULD, 1 COULD. The worst is the page **source** (`http` / `http_shell` / `browser` / `""` / `docs-resolution`): it is a free string decided in four places, consulted for cache validity in three (one of which forgets to), silently dropped at the docs boundary (`docs.PageContent` has no source), and its validity test depends on a process-local sticky flag (`browserBin` cleared on launch failure), so the same cache entry is "fresh" in one process and "stale" in the next. Two concrete bugs found in this class: a forced-browser failure in the crawler discards a good HTTP page (crawl.go:231), and `--force-browser` skips the status check that the 403 path uses, so a bot-wall's access-denied page passes as content (pipeline.go:333-339 → scrape.go:423). A third is a cache-bypass loop: a browser render whose tab cannot report its URL is refetched on every `docs` call and then refused as a scope error (docsfetch.go:108, web.go:1137).

## Machines

### Page source (fetch path) — MUST
- Where: declared scrape/scrape.go:32-41; decided at scrape.go:245 (403→browser), :258 (PDF→http), :327 (PDF conditional→http), :333-350 (`scrapeConditional`: http → likely_shell → `browserFetchOrWarn`), :455-481 (`maybeBrowserFetch`/`browserFetchOrWarn`: browser | http_shell), :408 (`renderedResult`→browser); consulted at scrape.go:538-546 (`CacheStaleForBrowser`), scrape/pipeline.go:117 (`CachedScrape` hit test), :147 (`CachedScrapeRaw` hit test — **no** staleness check), :198 and :232 (force paths accept only `browser`), crawl/crawl.go:213-235 (`fetchSource` local), :297 and :325 (crawl cache tests); overloaded at internal/docsfetch/docsfetch.go:40,49,61 (`"docs-resolution"` used as a type tag in the same field).
- States: `http` (authoritative), `http_shell` (shell, unrendered), `browser` (rendered; reached either via JS detection or via 403 retry — two different reasons collapsed), `""` (legacy entry, pre-source), `docs-resolution` (not a page at all).
- Transitions: detection `likely_shell` + browser ok → `browser`; `likely_shell` + no browser or render error → `http_shell`; 403 + browser ok (status<400) → `browser`; everything else → `http`. Cache: `http_shell` or (`""` and HasBrowser) → treated as miss (scrape.go:539-545).
- Today: string constants; `FetchResult.Source` comment at scrape.go:104 still says "SourceHTTP or SourceBrowser" though :345 can yield `http_shell`. The two reasons for `browser` (shell render vs bot-wall escape) are indistinguishable downstream.
- Risk:
  1. `CachedScrapeRaw` (pipeline.go:147) serves an `http_shell` raw entry even when a browser is now configured; `CachedScrape` (:117) would refetch it. Same key, two validity rules — the "short-circuit in one path but not the other" class from the brief.
  2. `CacheStaleForBrowser(source, s.HasBrowser())` reads a process-local flag that `getBrowser` clears on a failed launch (scrape.go:206-214). An entry is a miss in a process whose browser launched and a hit in one whose launch failed (e.g. bench replay, where the DevTools handshake is unrecorded — httpx/bench.go:30-33). Descendant of the "spent quota lived in one process but not the next" bug.
  3. `docsfetch.FetchPage` (docsfetch.go:106-120) returns `docs.PageContent{Title, Markdown, URL, Anchors}` — the source is dropped. The docs backend then re-derives shell-ness from link counts (`isShell`, docs/web_site.go:127-138) with a different heuristic than `extract.Detector`. Two detectors, no shared state, and the agent never learns that the "answer" came from an unrendered shell.
- Explicit form: `type Source uint8 { SourceUnknown, SourceHTTP, SourceHTTPShell, SourceBrowserRendered, SourceBrowserAfterForbidden }` plus a `Fetched struct { Source; Detection; Status int; FinalURL string }` carried on `Page`/`FetchResult`/`PageContent`. One function `(Source).UsableWith(browserState BrowserState, want Need) bool` replacing `CacheStaleForBrowser` and the three ad-hoc `== SourceBrowser` tests. Resolution entries get their own key space, not a fake source.
- Agent-visible: `fetched_via: http|browser|browser_after_403`, `rendered: false` on a shell, and a refusal reason `unrendered_js_shell` for the refusal floor instead of a low-similarity score on shell boilerplate.

### 403 → browser retry (bot-wall escalation) — SHOULD
- Where: scrape/scrape.go:500-516 (`browserOnForbidden`), :522-531 (`fetchVerified`: accept status<400 or 0), :615-638 (`FetchContentWithBrowser`: accept 2xx only and non-nil content — a second copy with a different acceptance rule), scrape/pipeline.go:332-341 (`classifyForForcedRender`: swallows **any** probe error when a browser exists), :313 (selector path), scrape.go:241 and :296 (callers); typed error scrape.go:589-596; docs mapping internal/docsfetch/docsfetch.go:211-217 (only 404/410 → `ErrNotFound`).
- States: plain-ok | plain-403 | plain-other-status | transport-error | browser-unavailable | browser-ok(status 0, trusted) | browser-ok(status<400) | browser-refused(status≥400) | browser-error.
- Transitions: only 403 escalates (scrape.go:502); browser nil → give up with original error (:506); render error → original error, stderr warn (:510-513); status≥400 → original error (:527-529).
- Today: `errors.As(*HTTPStatusError)` + `(rendering, bool)` + stderr prints as the only record of which branch ran. Acceptance rules diverge between `fetchVerified` (<400, 0 trusted) and `FetchContentWithBrowser` (2xx, non-nil body).
- Risk: `--force-browser` bypasses the verification. `classifyForForcedRender` returns `(nil, false, nil)` for a 403 (or DNS failure, 5xx, timeout) when a browser exists (pipeline.go:335-338), then `BrowserScrape` (scrape.go:414-444) calls `browserRender`, not `fetchVerified`, so a wall that refuses the browser too renders its access-denied page and it is extracted and **cached as `browser`** (pipeline.go:207, :241). The exact failure `fetchVerified`'s comment (scrape.go:518-521) guards against. Crawl's heuristic force path (crawl.go:231) has the same hole.
  For `docs`: a 403 with no browser reaches the backend as a generic upstream error (notFound maps only 404/410), so "the site refused us" is indistinguishable from "the site is down" — a different refusal reason for the lifecycle.
- Explicit form: `type fetchOutcome struct { Status int; Source; Escalated EscalationReason }` with one `escalate(ctx, fetchURL, err) (rendering, EscalationResult)` owning the 403 test, the browser lookup, and the single acceptance rule; `BrowserScrape` and `FetchContentWithBrowser` call it.
- Agent-visible: `refused_because: forbidden_no_browser` / `forbidden_browser_too`, `fetched_via: browser_after_403`.

### Browser availability (configured → connected → permanently unavailable) — SHOULD
- Where: scrape/scrape.go:195-218 (`getBrowser`: resolve or launch failure sets `browserBin = ""`), :174-178 (`HasBrowser` reads the same field), :477 (warn only when `!HasBrowser()`), scrape/pipeline.go:194-195, :228-229 (`ErrNoBrowser` from `HasBrowser()`), :335; consumers cmd/scrape.go:356-357 and mcp/scrape.go:186-187 ("requires a configured browser").
- States: unconfigured | configured-unresolved | connected | failed-sticky (reason lost after one stderr line).
- Transitions: first `getBrowser` call resolves and launches; any failure collapses to "unconfigured" for the rest of the process.
- Today: `browserBin == ""` means both "operator never set one" and "launch failed"; `ErrNoBrowser` text says "no browser configured" either way.
- Risk: (a) the staleness rule above flips per process; (b) an MCP server that hits one transient launch failure (Chrome busy, sandbox) renders nothing for its whole lifetime and reports a misleading config error; (c) in bench replay the launch fails by design (httpx/bench.go:30-33), so the suite cannot tell "no render needed" from "render blocked" — every shell silently becomes `http_shell`.
- Explicit form: `type BrowserState { Unconfigured, Configured, Connected, Failed{err} }` on `Scraper`, with `Failed` retryable after a backoff; `ErrNoBrowser` split into `ErrBrowserUnconfigured` and `ErrBrowserUnavailable{cause}`.
- Agent-visible: `browser: unavailable (launch failed: …)` in docs/scrape output; bench log event `browser_blocked`.

### Cache entry completeness (TTL × source × links × raw × final URL × anchors) — SHOULD
- Where: cache/cache.go:36-61 (five optional fields, each with its own sentinel), :144-150 (`Get`), :155-164 (`GetCrawl`: `Links == nil` ⇒ linksKnown=false), :166-184 (`getEntry`: TTL check), :220-241 (`GetRaw`: duplicate TTL check, `RawHTML == ""` ⇒ miss), cache/bbolt.go:135-200 (third freshness mechanism: stamp sweep); internal/docsfetch/docsfetch.go:108 (`FinalURL == "" || Anchors == nil` ⇒ bypass + `refresh`), :137-144; crawl/crawl.go:303, :313, :324 (three sites compute "usable at this depth").
- States per entry: expired | fresh × {source known?} × {links known?} × {raw stored?} × {final URL known?} × {anchors known?}.
- Transitions: `Put` (no links/raw), `PutCrawl` (links), `PutRaw` (raw); `refresh` rewrites via `Scrape` (not `ScrapeConditional`) so a docs refresh never back-fills raw/links.
- Today: nil-vs-empty pointers and empty strings as "unknown"; three freshness checks (getEntry, GetRaw, bbolt sweep).
- Risk: `FinalURL == ""` is both "legacy entry" and "the browser could not say where it landed" (scrape/browser.go:210-212, browser_iface.go:66-68, scrape.go:398). For the second, `docsfetch.FetchPage` refetches **every call** (the refreshed entry still has `""`), then returns `URL: ""`, which `servedFrom` turns into `scopeError{served:""}` → `ErrNotFound` ("came back without the URL it was served from", docs/web.go:1137). A renderable page becomes a permanent not-found plus a render per query. Also `ScrapeConditional`'s etag/304 machine (scrape.go:294-304, `FetchResult.NotModified`) is dead: the only production caller passes `"", ""` (crawl.go:220), and `CachedScrapeRaw` treats a 304 as an "unexpected" error (pipeline.go:156).
- Explicit form: `type entry struct { CachedAt; Source Source; Links Known[[]string]; Raw Known[string]; Final Known[string]; Anchors Known[[]Anchor] }` with `Known[T]{Value T; State knownState}` where state ∈ {unrecorded, unknowable, known}; one `func (e *entry) satisfies(need Need, browser BrowserState, now) (ok bool, why missReason)`; drop the etag path or make crawl use it.
- Agent-visible: `cache: hit|miss(reason)`; a docs answer that says `served_url: unknown (browser)` instead of refusing as not-found.

### Crawl item lifecycle — SHOULD
- Where: crawl/crawl.go:200-268 (`processItem`), :270-293 (`handleFetchedPage`), :295-317 (`processCachedItem`), :319-329 (`cachedFallback`), :28-35 (`Result.Status` strings), :218-236 (heuristic force-browser); background status cmd/crawl_bg.go:51-58 ("starting", parent), :103-110 ("running", child overwrites file incl. StartedAt), :83-86 and :131-134 ("failed"), :166-169 (file updated every 10 pages), :177-187 (final: stopped > failed > completed), :257 (`stop` requires "running"); crawl/status.go:17 (string with comment).
- States (per item): queued → cache-hit(usable) | fetching → fetched(http|shell|browser) | force-render → rendered | render-failed | failed → cached-fallback | reported-error | cancelled-silent. `Result.Status` ∈ {"new","changed","unchanged"} but "changed" is never produced (grep: only consumed at cmd/crawl.go:111, crawl_bg.go:157) and a fourth status ("unchanged but link discovery incomplete") is encoded as a `Result` with both `Page` and an `Error` string prefix (crawl.go:245-252).
- Transitions decided by the shared locals `page, rawHTML, doc, err, fetchSource, contentIsHTML` mutated across phases.
- Today: order-dependent mutation. **Bug:** at crawl.go:231 `page, rawHTML, err = c.scraper.BrowserScrape(...)`; `BrowserScrape` returns `nil, "", err` on failure (scrape.go:425), so a successful HTTP fetch is overwritten by a browser timeout and the item is reported as failed (or served from a stale cache fallback). Descendant of "a search hit's failure counted as the package's failure". Also, when `ScrapeConditional` already tried the browser and fell back to `http_shell`, the force path tries the browser a second time for the same URL (:230 tests only `!= SourceBrowser`).
- Background status: a worker that dies between "starting" and "running" (or is SIGKILLed while "running") leaves the file in that state forever; `crawl stop` either refuses (`!= "running"`, crawl_bg.go:257) or signals a possibly-reused PID (:261-265). Counters lag by up to 9 pages. "starting"/"running"/"completed"/"failed"/"stopped" are untyped strings written from two processes.
- Explicit form: `type itemOutcome struct { page *Page; source Source; links Known[[]string]; err error; stage Stage }` built by a pure `fetchItem` that returns the HTTP result and a separate `renderAttempt`, with one `report(outcome)` deciding `Result.Status` ∈ {new, unchanged, unchanged_incomplete, failed}. For background: `type CrawlState` enum with a `Liveness()` check (PID alive, UpdatedAt age) at read time.
- Agent-visible: `status: unchanged_incomplete`, `render: failed (kept http page)`; `ketch crawl status` reporting `running (stale: pid gone)`.

### JS-shell detection → render decision — SHOULD
- Where: extract/detect.go:62-102 (returns "static"|"likely_shell"|"ambiguous"); scrape/scrape.go:338-350 (parse error → "ambiguous"; only "likely_shell" renders), :456-460 (`maybeBrowserFetch`: same test, re-parses); crawl/crawl.go:331-361 (per-host stats: ≥10 pages and >80% `likely_shell` ⇒ force; "ambiguous" counts as not-shell).
- States: static | ambiguous | likely_shell | parse-error (folded into ambiguous).
- Transitions: a two-gate heuristic (visible text ≥200, script/text ratios 3× / 8×, markers) at detect.go:67-101; the crawl adds a second-order host-level decision.
- Today: three string literals, documented but untyped; `ambiguous` behaves exactly like `static` for rendering (scrape.go:344) yet is recorded in `FetchResult.JSDetection` as if it were a distinct outcome; a goquery parse failure is reported as a detection result rather than an error.
- Risk: for the refusal floor, `ambiguous` + `http_shell` pages produce near-empty markdown that will score low on similarity and be refused with the wrong reason ("no good match") instead of "page not rendered". The docs backend already has a second shell detector (`isShell`, web_site.go:127) that disagrees with this one by construction.
- Explicit form: `type Detection uint8 { Static, Ambiguous, LikelyShell, Unparseable }` returned by `Detector`; `shouldRender(d Detection, host hostStats) bool` in one place used by both scrape and crawl.
- Agent-visible: `detection: ambiguous` alongside `rendered: false` so the caller can decide to `--force-browser`.

### docs Fetcher outcome → docs error (cross-boundary mapping) — SHOULD
- Where: internal/docsfetch/docsfetch.go:83-97 (`FetchRaw`), :106-120 (`FetchPage`), :155-168 (`callerURL` four-way switch: "" | same | unrewritten | served), :176-184 (`unrewrite`), :211-217 (`notFound`: 404/410 only); consumers docs/web_site.go:32-52 (`profile`: raw → fallback to `FetchPage` unless `ErrNotFound || errRefusedRedirect || ctx.Err()`), docs/web_discover.go:1180-1220 (`readPage`: `rawErr`/`err`/`scope` triple), docs/web_fetch.go:181-218 (`fetchOne`), docs/web.go:1116-1144 (`scopeError` wraps `ErrNotFound` for both "redirected out of root" and "fetcher did not say").
- States of one fetch, as the docs backend needs them: ok-in-scope | ok-out-of-scope(served) | ok-unknown-origin | not-found(404/410) | forbidden(403, no browser) | rate-limited(429) | refused-redirect | transport/timeout | cancelled.
- Transitions: decided by `errors.Is`/`errors.As` chains in each of three docs call sites, each re-implementing "should I retry this through `FetchPage` (the browser)?".
- Today: `error` values as control flow; `docs.PageContent`/`RawContent` carry only URL/body; 403, 429, 5xx and timeouts all collapse into "retryable upstream".
- Risk: the three sites already drift (profile falls back on any non-404 raw error including 403 — "bot protection may still let the browser through", web_site.go:42 — but `rootNav` at web_discover.go:1157-1170 gives up on any error). The upcoming lifecycle (local → web → Context7, each with refusal reasons) will need these outcomes as values, not as `errors.Is` ladders.
- Explicit form: `docs.FetchOutcome { Kind OutcomeKind; Status int; ServedURL string; Source Source; Err error }` returned beside the content; `notFound` becomes `classify(err) OutcomeKind` in one place; `servedFrom` consumes `ServedURL` with its known/unknowable state.
- Agent-visible: `refused_because: forbidden | out_of_scope(served) | unverifiable_origin | not_found | upstream_timeout`.

### Bench hook mode and per-key sequence — COULD
- Where: httpx/bench.go:123-155 (`loadBench`: mode from env presence; `s.err` sticky), :157-190 (`RoundTrip` switch order replay > record > live-log), :120 (`next` map means "next seq" in record, "served count" in replay), :307-372 (`serve`: miss | reused | error-replay | body-missing), :549-560 (mode derived a third time for logging).
- States: off | live-log | record | replay | config-error(sticky).
- Risk: mostly tidiness, but one observability gap matters for the audit's purpose: "reused" (bench.go:322-325) silently serves the last recorded response when replay makes more requests than the recording did — a behavioural drift between runs (e.g. an extra probe) becomes invisible except in the optional log. The missing-body case shares `ErrUnrecorded` with the missing-exchange case (:320, :347).
- Explicit form: `type benchMode uint8` set once in `loadBench`; `next` split into `recordSeq`/`servedCount`; a distinct `ErrReused`/`ErrBodyMissing` or a `strict` env to fail on reuse.
- Agent-visible: a replay summary (`misses`, `reused`, `browser_blocked`) the bench harness can assert on.

## Already explicit
- `HTTPStatusError` (scrape/scrape.go:584-596): typed, carries status and URL, matched with `errors.As`; consumers (403 retry, `notFound`) read the code not the text. Fine.
- `rendering` (scrape/browser_iface.go:51-55) and `browserRender` (:69-82): one struct for html/status/finalURL with documented zero-value meaning ("0 trusted", "" unknown); the capability detection is a clean type switch.
- Selector sentinels `ErrBadSelector`/`ErrSelectorNoMatch`/`ErrPDF*` (scrape/pipeline.go:36-46): mapped once each in cmd/scrape.go:350-361 and mcp/scrape.go:180-205.
- `FetchResult.Doc` nil contract (scrape/scrape.go:97-102, crawl.go:224, :346): documented and honoured at every write.
- httpx redirect check (httpx/redirect.go:22-66): one owner (`CheckRedirect`), composition explicit, `WithoutRedirectCheck` for the opt-out.
- `Exchange` (httpx/bench.go:88-104): a real record type; `replayedError` preserves `Timeout()`/`Is` classes.
- `rodConn.FetchContent` document interception (scrape/browser.go:218-250): state is a channel select, bounded by one timeout.

## Cross-area edges
- `scrape.Scraper.ScrapeMarkdown/Scrape` → `internal/docsfetch.Fetcher.FetchPage` → `docs.PageContent` (docsfetch.go:106-120): Source, JSDetection and HTTP status are dropped here; `FinalURL` becomes `URL` via `callerURL`.
- `docsfetch.notFound` → `docs.ErrNotFound` (docsfetch.go:211-217) → `cmd/exit.go:65` (exit 3) and `mcp/errors.go:63` (`[not_found]`): only 404/410 cross; 403/429/5xx cross as generic errors.
- `docs/web_site.go:176-183` (`publicHops`) → `httpx.WithRedirectCheck` → `httpx.CheckRedirect` on every hop of the plain client; explicitly does **not** reach a browser render (comment :172-175), so the scope check on `Page.FinalURL` is the only guard on that path — and `FinalURL` can be `""` (machine 4).
- `scrape.ErrNoBrowser` → `cmd/scrape.go:356` / `mcp/scrape.go:186` (precondition): conflates unconfigured with launch-failed (machine 3).
- `crawl.Result` → `cmd/crawl_bg.go:146-170` (status counters, every-10-pages file write) and `cmd/crawl.go:111`: the never-emitted "changed" is counted there.
- `cache.Cache.putEntry` → `Backfill` tag metadata (cache/cache.go:270-276): a tag-store failure is swallowed to stderr; outside this area.
- `httpx/bench.go` replay → go-rod DevTools handshake unrecorded → `scrape.getBrowser` launch failure → sticky `browserBin=""` → every `likely_shell` page becomes `http_shell` for the process (bench.go:30-33, scrape.go:210-214). The bench cannot observe this transition.
