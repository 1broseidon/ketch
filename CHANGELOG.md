# Changelog

All notable changes to this project will be documented in this file.

Each version's section is its release notes: what changed for the person
using ketch, written as prose, not a list of commits. The section is published
verbatim on the GitHub release. Versions follow
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

**Index a library's docs once, then answer questions about it offline: `ketch docs index` and the `local` docs backend.** `ketch docs index fastapi` (or a docs URL, such as `https://docs.astro.build/en/`, or any spec `-b web` takes: `django@5.2`, `pypi:click`, `owner/repo`) finds the docs root the way `-b web` does, refusing an ambiguous or unverified name with its candidates (exit 2 or 3) so you can pass the docs URL you mean; reads the site's own page lists (`llms.txt`, `llms-full.txt`, sitemaps, its search index and nav links); keeps only the pages under that root in its locale and version, leaving out translations and other versions' trees; honours `robots.txt`; fetches up to `--max-pages` pages (1,500 by default), four at a time, through the scrape pipeline and page cache; splits them into heading sections, never inside a code block; and stores them with a full-text index of them in `docs-index.sqlite` in ketch's cache directory (SQLite, through a pure-Go driver: no CGO), apart from the page cache and the bookmarks. No model runs: a 735-page site indexes from the page cache in seconds. When a site has more pages than the cap, the pages its `llms.txt` lists go first, then guides and tutorials, then everything else, and generated API reference leaves and release notes last, so NumPy's user guide is indexed rather than a thousand generated reference pages; `x` and `x.html` are one page, `/llms/` text mirrors are left out, and a page whose text is another's (including a missing page served as the home page) is dropped. `--dry-run` prints the pages a build would index, in order, without fetching them. A root that stands for a release (DuckDB's `/docs/stable/` is `/docs/2.0/`) is indexed at that release, an unversioned root whose pages or `llms.txt` sit in release directories (CrewAI's `/v1.15.35/`, Hugging Face's `/v5.22.1/`) is indexed at that release and shown under the unversioned addresses when its pages name them canonical, and a version's own host that serves an app shell for its sitemap (`v18.angular.dev`) is given the current host's paths to try. Progress goes to stderr and a summary (pages, sections, time, index size) to stdout, or `--json`. One index is one version of a library: `vue-router@3` (or `--version 3`) indexes that version's docs root (`v3.router.vuejs.org`), and a name alone the current docs, labelled with the package's latest release when the site names none; other versions' trees below the root (a tree the site's version list names, Docusaurus's `/docs/2.x/` and `/docs/next/`, mike's version directories, a tree mostly of copies) are left out and counted. Several versions of a library sit side by side, each under its own docs root, and a page in the tree about a later major (a v3 page "Migrating to v4") is kept but labelled, and ranks lower unless the question is about migrating. Running it again fetches the pages through the page cache and re-sections only those whose content changed, and drops pages the site no longer lists; `--list` and `--remove` manage it, and `--name` adds a name to call the library by. A library answers to its full names only (its package and repository names, the name it was indexed by, its docs site's own name, its docs host's label), never to one word of a longer name, so with only Vue Router indexed a question about `vue` is `not_indexed` rather than answered from Vue Router's docs; a name without a version answers from the current docs of exactly that project, so with `angular@18` and angular.dev indexed, `angular` answers from angular.dev, and `svelte` from Svelte's docs rather than SvelteKit's. Then `ketch docs -b local --library fastapi "how do I run code after the response is sent"`, or a bare query that names an indexed library, answers with no network in tens of milliseconds with whole sections: the question is ranked by keywords over the full-text index (bm25, a heading counting three times the text; identifiers such as `useForm`, `client_max_body_size` or `form.validateField` found by their whole name or their words; question filler such as "use" or "need" ignored; guides ahead of API reference leaves, and a page whose sections match the question ahead of a stray section elsewhere), and each of the best five results is a section under its second-level heading with the subsections of it that matched, verbatim with its code, within about 1,800 tokens (`--tokens` and `--limit` change both); a long section keeps its lead, its first code block and the paragraphs that name the question (marked `[…]`). Each is printed as `### heading path`, the text and `source: url#anchor`, and in `--json` carries `anchors`, every section it shows. Results carry `source: local`. `--library vue-router@3` answers from that version's index alone, and a version that is not indexed exits 3 with reason `not_indexed`, naming the versions that are; without a version the newest indexed one answers, and `version:` (each result's `version`) says which. A library the index does not hold exits 3 with reason `not_indexed`, and nothing matched exits 3 with `no_results`. The `auto` docs backend now asks the local index first whenever it holds the library, then `web`, then Context7, and lists every backend it tried; a library the index does not hold is not an attempt, so `auto` behaves exactly as before until you index something. The default docs backend is unchanged. The MCP `docs` tool takes `backend: "local"` and gains a `note` field; building an index stays on the CLI.

**`-b local --tokens N` fits its answer to N tokens, compactly, so an agent's small budget holds four or five results instead of two or three.** The default answer (whole sections, about 1,800 tokens) is unchanged. With a budget (MCP `tokens`), tokens are counted as an LLM's tokenizer counts them (an estimate of o200k within about 4% on a result, where four bytes a token was off by 9% and undercounted code by up to 37%), and the same ranked results are rendered compactly: each gets a share of the budget weighted by its rank (the first the largest), a section that fits its share is shown whole, and one that does not keeps its heading path, its first sentence, the code block that names the question (else its first) whole with the sentence leading into it, and the sentences that name the question best, then whatever else names it; subsections that did not rank are left out, code is never cut, and one `[…]` ends a result that leaves anything out instead of `[truncated]` markers. At 880 tokens on the 63 dev questions this shows 4.4 results where 2.7 whole sections fitted, puts the right section within the budget in 55 cases (43 for whole sections packed into 880 tokens, 54 for the old trimming at `--tokens 880`), and keeps the questions' required facts in 39 answers against 29 for the old trimming (40 for whole sections in fewer results); no answer runs over its budget, where the old trimming reached 1,113 tokens at `--tokens 880`. A page indexed at two addresses (`x` and `x.html`, or an `/llms/` text mirror, in indexes built before builds merged them) no longer repeats a section in one answer, and an API reference page gives one result while other pages rank next. `ketch docs index` of an unversioned root whose pages sit in several releases' trees (sequelize.org's `/docs/v6/` and `/docs/v7/`) indexes the site's default docs, the release its home page links to, and leaves the other releases out; a translation's `x.html` copy of a page `llms.txt` lists as `x` is now left out with its locale (Vue Router's `/zh/` pages were kept). Names: `--library svelte` answers from Svelte's docs rather than SvelteKit's when both svelte.dev indexes were built from their URLs (a path segment names a library before its host does), `httpx` names python-httpx.org and `poetry` python-poetry.org (a host label without its language word), and `beautifulsoup4` finds Beautiful Soup's docs.

**A compact local answer tells the agent where to read the rest, and `ketch docs --section` reads it: a follow-up that costs no network and no quota.** At `--tokens 880` the compact answer sometimes trims away the one code example a how-to question needs (Mantine's `useForm` `validate` rules, Angular's `computed(() => ...)`, Transformers' `add_generation_prompt=True`). The full section is already in the local index, so every result a compact answer cut short (the ones ending in `[…]`) now ends with a one-line pointer after its `source:` line, `full section: ketch docs -b local --section <url#anchor>` (over MCP, at the end of the `snippet`: `full section: docs(backend="local", section="<url#anchor>")`), and results shown whole have none. The pointer is counted in the budget, so an answer still stays within it: a cut result costs about 25 tokens more, and the budget gives a result a little more room (a fifth result is dropped sooner). `ketch docs -b local --section <url#anchor>` (MCP: the `docs` tool's new `section` argument, which takes no `query`) returns that one section from the index in the shape of a result, its heading path, its text with every code block intact and `source: url#anchor`, with no ranking and no network, in tens of milliseconds; `--library` is optional because the URL names the indexed library. An anchor on a second-level heading returns the whole family (its text and the subsections under it), a deeper one that section and what is under it, and a page URL with no anchor the page's sections in order. `--tokens` caps it (default 4000); a longer section is cut at a block boundary, never inside a code block, and ends with `[…]`, the cap, and the next section to read (or to raise `--tokens`). An unknown page or anchor exits 3 with reason `not_found` (MCP `[not_found]`), naming the page's anchors; a malformed reference exits 2; `--section` with another backend exits 2. `--json` and the MCP results gain `section` on every local result (the reference to pass) and `truncated: true` on a result that left text out, in the default view as well; the default (no `--tokens`) text output has no pointer. For Go importers: `docs.Result` gains `Section` and `Truncated`; `docs.SectionFetcher` (implemented by `Local.SectionSelect`), `docs.ErrSectionNotFound`, `docs.HintStyle` (`HintNone`, `HintCLI`, `HintMCP`), `docs.SectionHint`, `docs.SectionCall` and `docs.RenderResult`; `docs.LocalOptions` gains `Hint`; and `docsindex.Store.PageSections` reads one page's sections without a pass over the library.

**The local index runs no model: it ranks by keywords, answers in tens of milliseconds and builds in seconds.** Nothing is downloaded and nothing is embedded; `ketch docs index`, `-b local` and the auto chain need no setup beyond the index itself. An embedding model fused with the keyword ranking was built and measured side by side, and left out because it cost far more than it bought: on 63 gold-labelled library questions keywords alone put the right section first 38 times against 37, in the top five 51 times against 55, answered 46 against 47, and answered within an 880-token budget 43 times against 42, at 32 ms a query instead of 202 ms; embedding a 735-page site took 13 minutes and 2.5 CPU-hours at 1.6 GB of memory, where keywords alone index it in seconds and 2.4 CPU-seconds. `ketch doctor` gains a `docs local` row with the number of libraries indexed, without touching the network. The design is ADR-0007 (amendment 5 for the full-text index, amendment 7 for leaving the model out), which supersedes ADR-0004's rejection of a local docs corpus.

**Keyless `web` verifies more real docs sites without a GitHub token, and stays out of a deprecated namesake's way.** Four more independent pieces of evidence now count toward the two a keyless pick needs: the package's own README (as the registry publishes it) linking to the docs site; a project's home page vouching for a docs subdomain of its own domain; a repository that moved, followed with a plain request to github.com rather than the rate-limited API; and the other URLs a package's metadata publishes (download, tracker, funding links) witnessing that a root is on the owner's domain. A deprecated npm package of the same name is weighed as a rival only against a pick whose only docs a package index hosts, so it no longer makes a library with its own docs site ambiguous. A README links its dependencies', sponsors' and parent frameworks' sites too, so its link counts only for a site that names the package (its title, site name or `llms.txt` heading) or links back to the package's own repository or registry page, and never for a site named after another project it links (an extension's README pointing at the framework it extends no longer makes the framework's docs the extension's: the name is refused); a root only a README ties to the package also ranks after the docs its metadata or its registry names.

**Blog posts are no longer docs.** A docs root never takes in the blog, news, posts, announcements, showcase or community sections below it, nor dated post paths such as `/2019/08/slug` (unless you pass a root inside one), in `-b web` answers and in `ketch docs index` alike; and a root that lands on a site's home page whose docs live in a section of their own (a landing page whose Docs link leads into `/docs/`, a `docs.` host of the same domain) is that section, as a package's homepage already was.

**Fixed** code highlighted with hover popups (Shiki's twoslash, as VitePress sites such as hono.dev and router.vuejs.org use) coming out one token per line: a block element inside a line's inline markup no longer breaks the line, so `app.notFound((c) => …)` reads as written, in `ketch scrape`, `-b web` and the local index alike.

**Fixed** code samples in tabs going missing: a page that hides every tab but the first until a script shows it (an inline `display: none` or a `hidden` attribute, as AWS's XML/JSON lifecycle examples do) lost the hidden tabs' code. A hidden block holding code the page shows nowhere else is now kept, a hidden copy of visible code is still dropped, and an ARIA tab's label (npm, yarn; Python, Go) is written as a bold line above the code it shows instead of the labels running together above unlabelled blocks, in `ketch scrape`, `ketch extract`, `-b web` and the local index alike.

**Fixed** the version and locale collapse treating a page's last path segment as a version when the URL ends in a slash: `/tutorial/1-setup/2/` and `/guides/upgrade-to/v5/` are pages of their own, not copies of `/tutorial/1-setup/` and `/guides/upgrade-to/`. Only a landing page whose every segment is a locale or version (`/stable/`, `/en/5x/`) is one.

A web docs call no longer fetches the same URL twice: the files and pages one call reads at several stages (a root page, its `llms.txt`, a large registry page) are fetched once and shared within the call, and a discovery file that timed out is not waited on again under the same timeout.

For Go importers: `docs.Local` (`NewLocal`, with `SearchSelect`, `GetDocsSelect` and `ResolveSelect`), `docs.IndexLibrary`, `docs.IndexRequest`, `docs.IndexReport`, `docs.MatchIndexed`, `docs.ErrNotIndexed`, `docs.ErrIndexOutdated`, `docs.OpenIndex`, `docs.LocalOptions` with `docs.WithLocalOptions`, `docs.RenderSnippet` and `Auto.WithLocal`; `docs.Outcome` gains `Note`; `docs.SelectingSearcher` is implemented by `Local` as well as `Auto`; `config.AvailableDocBackends` includes `local`; `httpx.HasRedirectCheck`; and `docs.FTS5Local`, a stub that never answered, is removed.

**Fixed** `ketch scrape --raw` serving a cached copy of a JavaScript page that was never rendered. A page fetched as an unrendered JS shell is never served from the page cache, so a later call renders it; the `--raw` path skipped that rule and returned the shell. Every cached read path now applies one rule (`scrape.Source.ServeFromCache`), and it depends on whether a browser is configured, not on whether one launched in this process, so a browser that failed to start no longer makes the same cache entry fresh in one ketch process and stale in the next. A page rendered by a browser that could not report where it landed is no longer fetched again on every docs call. For Go importers: `scrape.Source` is a named type (`SourceUnknown`, `SourceHTTP`, `SourceHTTPShell`, `SourceBrowser`) used by `scrape.PageCache`, `cache.Cache` and the fetch results; `scrape.Page` gains `Source` and `FinalURLUnknown` (not part of the page's JSON); `Scraper.BrowserConfigured` and `Scraper.ServeFromCache` replace `scrape.CacheStaleForBrowser`; and `docs.PageContent` gains `Shell` and `Rendered`.

**Every `ketch docs` call ends in one of four named states, and an empty answer is a refusal.** A docs request is now `answered`, `partial` (results, but the backend could not finish), `refused` (the request must change: no library named, ambiguous, nothing verified, no such version, nothing matched) or `failed` (a source down, rate limited, timed out, not configured), with a short reason, decided in one place (`docs.Outcome`) and rendered the same way by the CLI and the MCP server. A search that found nothing used to exit 0 with `result_count: 0` (and `null` under `--json`), and over MCP came back as a success with no results; it is now a refusal, exit 3 (`[not_found]`, reason `no_results`), so an agent can tell "nothing matched" from an answer. For the same reason the `auto` docs backend now hands an empty web answer to Context7 like any other refusal, under the same rule that Context7's pick must be a library the query names. The MCP `docs` tool's output gains `status`, `reason` (for a partial answer), `backend` for every backend, and `attempts`: each provider tried, in order, with its status and reason; `errors` is kept. On the CLI, the warning for a provider the auto chain fell through names its status and reason (`warn: web refused (ambiguous): …`), and a partial answer prints `status: partial (<reason>)` before `result_count`. A timeout inside the web backend now carries the reason `timeout`. For Go importers: `docs.SelectingSearcher`'s methods return a `docs.Outcome` (`docs.Selection` and `docs.BackendError` are gone), and `docs.Answer`, `docs.Resolved` and `docs.ErrNoResults` record a single backend's call the same way.

**Error classes are decided in one place, and two of them changed.** The CLI's exit codes and the MCP tool error prefixes now come from one classifier (`internal/failure`), and each error ketch defines carries its class where it is defined, so the two surfaces cannot disagree again; one test table checks both. Two failures move to the class ADR-0002 already gave them. A timeout (a backend that took too long, or the HTTP client's own limit) is now `[upstream]` over MCP, as it already exited 4 on the CLI; it was `[cancelled]`, which now means only that the client cancelled the call. A cache or bookmark file locked by another ketch process now exits 4 (`[upstream]`: try again) instead of 5 (`[precondition]`), since nothing needs configuring.

**Context7 works without a key, and a new `auto` docs backend asks the keyless web backend first and Context7 second.** With no `context7_api_key`, `ketch docs` and the MCP `docs` tool now call Context7 with no `Authorization` header instead of refusing, on Context7's anonymous quota: about 200 requests a month per IP address, shared by everything on that address, renewing at the start of the month. That is small; a bare docs search spends two requests (resolve, then fetch), and a free key lifts the cap exactly as before (`ketch config set context7_api_key <key>`); keyed requests are unchanged. When the quota is spent, Context7's 429 (or an error with `ratelimit-remaining: 0`) exits 4 (`[upstream]`) with a message naming when the quota resets and the `config set` command, and once a response has said the quota is spent, ketch stops asking until the reset rather than spending a request to be told again — in later ketch processes too, for up to a day (the anonymous quota belongs to an IP address, which can change). The last quota Context7 reported is kept in a small file in ketch's cache directory (`context7-quota.json`, keys stored only as a hash). A library Context7 has moved (`/facebook/react` now answers with a `library_redirected` pointing to `/react/react`) is followed once, and the results carry the new ID. `ketch doctor` reports keyless Context7 as `ok` and `keyless` without sending it anything, from that file: the requests left as of the last response and the reset time, or `quota not yet seen`, so running doctor never spends the quota; a spent keyless quota is `no_key`, instead of `no_key` for every install without a key. `-b auto` (or `docs_backend: auto`) chains the two the way `search`'s auto chains search providers: web answers first, and Context7, keyless or keyed, is asked only when web refuses (it identified no library, the one named does not exist, a source failed, or the name is ambiguous), never to replace an answer web gave, and never when you name a provider with `-b`. An ambiguous name is answered from Context7 only when Context7's pick is one of the candidates web listed, by the same GitHub repository or the same docs site; otherwise the ambiguity error stands and names Context7's pick, because docs for the wrong project are worse than none; for any other refusal Context7's pick must be a library the query names (its title or repository name is one of the query's words, or two of them run together), since Context7 reads a whole question fuzzily and can answer `useState in react` from an unrelated React Native library. A library pinned to an ecosystem or version (`npm:react`, `react@18`) or given as a docs URL stays web's, a Context7 ID passed as `--library` goes to Context7, and `--resolve` lists Context7's matches only when web has none. The `backend:` line (the MCP `backend` field) and each result's `source` say which provider answered, web's refusal is printed as a warning (MCP `errors`), and when both fail the error is web's, with its exit code, followed by Context7's. The default docs backend is unchanged (Context7) until keyless web passes its accuracy gates; `auto` is opt-in. For Go importers: `docs.RateLimitError`, `docs.AutoBackend`, `docs.Auto` (`NewAuto`, with `SearchSelect`, `GetDocsSelect` and `ResolveSelect` reporting a `docs.Selection`), `docs.SelectingSearcher`, `docs.SelectableBackends` and `docs.IsBackend`; `config.AvailableDocBackends` now includes `auto`, and `docs.SupportsLibraries("auto")` is true.

**`ketch docs` can read a library's own documentation site, with no API key, and find the site from the library's name.** Pick the new `web` backend and name the library: `ketch docs -b web --library click "nested commands"` looks `click` up in npm, PyPI and crates.io, checks each package's repository on GitHub, and searches the docs site the evidence points to, returning the sections that match, each with its heading breadcrumb and a link to the heading's anchor, within the `--tokens` budget. The library can also be the docs URL itself (`--library https://docs.astro.build`), a package with its registry or version (`pypi:click`, `npm:@astrojs/starlight@0.30`, `django@5.2`), a GitHub `owner/repo`, or a Go module path, and a bare query can name it: `ketch docs -b web "how do I set retries in requests"` searches the requests docs for retries, and the output's `library:` line shows the docs root a name resolved to. A site counts only on evidence: the package's registry entry or its repository names it, the homepage they name links to it as its docs, or it is the package's page on docs.rs or pkg.go.dev, and a site found any other way must be on the project's own domain and link back to its repository. So `click` is PyPI's Click, not the npm package of the same name, whose repository is gone, and a mirror of a project's docs is never taken for them. `--resolve click` shows what was found and why: the docs root URL, which is the ID to pass as `--library` from then on, since a name is resolved again on every call; a trust score from 0 to 10 worked out from the evidence; the version the docs are for and the versions the site offers; the package specs; and an `evidence:` line. `--json` and the MCP `matches` carry these as `version`, `versions`, `packages` and `evidence`, and Context7's resolve output is unchanged. `@version` takes an exact label, an alias such as `stable` or `dev`, or a prefix (`5` for the newest 5.x, never crossing a major version), and finds that version's docs in the site's own version list, from Read the Docs, a version switcher, or the links between versions; a version the site does not offer exits 3 (`[not_found]` over MCP) and lists the versions it does. A name more than one verified project answers to, with none far ahead of the rest on GitHub stars, exits 2 (`[validation]`) with each candidate's ID and package specs, so you can pass the one you mean; `--resolve` lists them all instead. A same-named package whose only docs a package index hosts (docs.rs, pkg.go.dev, pythonhosted.org), or whose repository is gone, never makes a popular name ambiguous, so `fastapi`, `requests` and `clap` are the libraries you expect. A package's repository counts only when the repository backs the claim, through a GitHub homepage that names the package's site, or by being named like the package and written in its registry's language, so a package that claims a popular repository borrows neither its stars nor its place, and a homepage's docs link to another domain counts only when that site links back to the repository. ketch reads what the site publishes for this, cheapest first: its `llms.txt`, the `llms-full.txt` beside it, its sitemaps (from `robots.txt` or the usual locations), and finally the links on the docs root page, then fetches only the few pages that best match the query. It stays inside the docs root: the same host (`www.` counts as the same) and paths under it, so `--library https://example.com/docs/` never answers from the blog, and a page that redirects off the site or out of that path is dropped rather than shown under the address it was listed at. A URL naming a file, such as `…/guide/index.html` or `llms.txt`, means the directory holding it. Pages go through the same pipeline as `ketch scrape`, so URL rewrites, cookies, the browser fallback and the page cache apply. A query that names no library ketch can verify exits 2 and says to pass `--library`; a library that no registry or repository has, or for which nothing verifies, exits 3 with each candidate's reason, as does a docs root that does not exist; and a registry, GitHub or a site that is down or too slow exits 4 (`[upstream]`). Where one library is needed, a registry or GitHub search that fails exits 4 even when something else verified, naming the docs root that would have been picked, rather than answering from what was left; a bare query does the same, rather than reading a weaker library out of the query, when the failure could have changed the library it picked, and `--resolve` lists what answered with an evidence note that the list may be incomplete. Redirects of the third-party URLs a name leads to are checked hop by hop and never followed into private or loopback addresses; a page the browser renders follows its redirects itself, but one that ends outside the docs root is still dropped. Resolving a name asks GitHub about each repository, which allows 60 requests an hour without a token, so `gh auth login` or `github_token` helps; when the limit is reached ketch still answers from the registries and notes it in the evidence. The MCP `docs` tool takes the same `backend: "web"` and `library`. For Go importers, `docs.LibraryMatch` gains `Version`, `Evidence` and `Packages`, omitted from JSON when empty; an ambiguous name is a `*docs.AmbiguousLibraryError`, which matches `docs.ErrAmbiguousLibrary` and `docs.ErrLibraryRequired`; `docs.Provider` gains `LibraryHelp`, which the CLI and MCP help text are built from; `docs.NewFromConfig`, `Provider.New` and `Provider.Build` take a `docs.Deps` (the zero value is valid), whose `Fetcher` reports where each response was finally served from; and `scrape.FetchedContent.URL` and `scrape.Page.FinalURL` (not part of the page's JSON) give the URL after redirects.

**Fixed** `ketch tag show`, `tag list` and `tag add` reporting a bookmark with a `#fragment`, such as a docs section, as not cached when its page was. The fragment never reaches the server, so the page's cached body is the bookmark's; each section is still its own bookmark, removed by the URL shown.

## [0.20.2] - 2026-10-30

**The pi package works on Windows when npm installed ketch.** npm puts a `ketch.cmd` shim on PATH, and Bun refuses to pass an argument containing a cmd.exe metacharacter (a quote, `&`, `^`) to a batch file. `ketch_scrape` sends its URLs as one JSON-array argument and `ketch_tag` can carry a quoted value, so both failed with `[upstream] ketch could not be started: … contains a cmd.exe special character`. The tools now resolve the native `ketch.exe` behind the shim and run it directly, so no shell sits between the tool and ketch; the resolved path carries no version, so an npm upgrade needs no reconfiguration. An unknown layout keeps the plain `ketch` lookup, and the new `KETCH_PI_BIN` names a binary explicitly. The package's own tests build a `ketch.exe` on Windows and point the extension at it, so `npm test` passes there now.

## [0.20.1] - 2026-10-28

**Go toolchain patched to 1.26.10.** Release binaries are now built with Go 1.26.10, which distrusts a set of compromised intermediate certificates in `crypto/x509` ([GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809)), reachable from every HTTPS fetch. Building from source now needs Go 1.26.10 or newer.

**HTML parser patched again.** `golang.org/x/net` moves to v0.62.0, which fixes quadratic-time text-node coalescing ([GO-2026-6860](https://pkg.go.dev/vuln/GO-2026-6860)) and a raw-text namespace check when rendering HTML ([GO-2026-6866](https://pkg.go.dev/vuln/GO-2026-6866)), both reachable from extraction.

**Choose the order `auto` searches in.** The new `search_order` key takes a list of backends, e.g. `ketch config set search_order exa,tinyfish,brave` (or a JSON array), and `KETCH_SEARCH_ORDER` overrides it with a comma-separated list. When it is set, `auto` tries only those backends, in exactly that order: a configured provider is not promoted past it and the default ranking no longer applies, so a keyed provider or a SearXNG instance on its localhost default can be listed too. A listed provider that is missing its key or instance drops out of the chain; if none is left, search fails with an error naming `search_order`. `auto`, unknown names and duplicates are rejected by `config set`, by the environment variable, and when the chain is built from a hand-edited file. Unset, `auto` behaves exactly as before. `ketch config` shows the key, `ketch doctor` reports the chain in the operator's order, and the MCP `search` tool follows it with no new parameter; `--multi`, `--random` and `-b <provider>` are unaffected. Thanks to the reporter of [#80](https://github.com/1broseidon/ketch/issues/80).

**Blank entries in `KETCH_SEARCH_ORDER` now fail validation.** Leading, trailing or repeated commas and whitespace-only entries report `backend name is blank` instead of silently changing the chain or clearing the file's pinned order. An entirely empty environment value remains unset.

**A 403 is retried through the browser when one is configured** (#81, thanks @ArdaYILDIZ-DEV). Bot walls such as Cloudflare and Akamai often answer ketch's HTTP client with 403 but let Chromium through, and the only way past them was to run the scrape again with `--force-browser`, which over MCP cost an agent a second call. Now, when the plain fetch gets HTTP 403 and a browser is configured, `scrape` (including `--raw` and `--select`), `search --scrape` and `crawl` fetch the page through the browser and print `notice: HTTP 403 for <url>; fetched with the browser` to stderr; stdout and `--json` output are unchanged, and the page is cached as a browser render. Only 403 escalates: a 429 means back off, so it and every other error status fail as before without touching the browser. If the browser fails as well, or is itself answered with an error status, the error is still the original `HTTP 403 for <url>`, with the browser's failure as a stderr warning. This also covers `crawl --sitemap` seeds and child sitemaps, preserving the original XML rather than Chromium’s XML viewer or stylesheet output. Failed sitemap retries retain the original 403 and never enter the page cache. Without a browser configured nothing changes. For Go importers, a non-200 fetch now returns a `*scrape.HTTPStatusError` carrying the status code and URL, with the same message as before.

## [0.20.0] - 2026-10-20

**A config file with a type error now fails instead of resetting to defaults.** A hand-edited config file that wasn't valid JSON, or gave a key the wrong type (a number where a string belongs, or an `http_headers` value written as `["id"]` instead of `"id"`), was silently replaced by the built-in defaults, every key in it, so a `searxng_url` or `firecrawl_url` pointing at a private instance quietly fell back to a public backend. A config file that exists but can't be read fails the same way. `ketch config set` now refuses such a file rather than rewriting it from defaults, which used to drop every other setting in it; `ketch version` and `ketch config path` still work. An invalid `http_headers` now exits 2 for a wrong type as well as for a bad shape or value. For Go importers, `config.LoadFile` now returns `(Config, error)`.

Tool input never reaches the CLI as options: values follow `--`, scrape URLs travel as one JSON array, and crawl `allow`/`deny` patterns are CSV-quoted. Results render as compact summaries in pi (titles, domains and snippets for search, page counts and errors for crawl), with the full response one Ctrl+O away and the model still receiving everything. The package never bundles the binary; when `ketch` is not on PATH the tools fall back to the pinned npm wrapper (`npx -y ketch-cli`), so Node alone is enough, and `KETCH_PI_NO_NPX=1` turns that off. With neither available a tool returns a `[precondition]` error naming `brew install ketch`, `npm i -g ketch-cli` and `go install`. The manifest is the new root `package.json`; `npm test` runs the extension's unit tests without pi installed. The skill's frontmatter moves `version` under `metadata`, where the Agent Skills specification puts it, so pi loads it without a warning.

**Parallel accepts an optional API key.** Parallel's Search MCP stays keyless by default; set `parallel_api_key` (or `KETCH_PARALLEL_API_KEY`, which takes a comma-separated list) to send it as a Bearer token and get Parallel's higher limits. `parallel_api_keys` rotates several keys like the other providers, a configured key promotes Parallel in `auto`, and `ketch doctor` reports a rejected key as misconfigured. Credential errors name the key by position (`key 1 of 2`), and a key the service echoes back into an error, a response body, or a redirect is replaced with `[redacted]` in errors and doctor output. Without a key, requests, errors, and doctor output are unchanged.

**Patched HTML parser and Go toolchain.** ketch parses arbitrary web pages with `golang.org/x/net/html`, and the version it shipped with had known denial-of-service and parsing flaws reachable from extraction; it now uses `golang.org/x/net` v0.61.0 and `golang.org/x/text` v0.43.0. Release binaries are built with Go 1.26.9, which fixes a set of `net/http`, `crypto/tls` and `net/textproto` advisories, so building from source now needs Go 1.26.9 or newer. CI runs `govulncheck` on every change (`make vulncheck` locally).

**`http_headers` values no longer reach instance errors or `ketch doctor`.** A SearXNG, Firecrawl, Degoog, or Sourcegraph instance that echoed a header value back could get it into the error ketch printed, or a doctor detail, through a response body, or through the URL or `Location` that Go's HTTP client quotes when it cannot follow a redirect. Every instance error and doctor detail now has every configured `http_headers` value replaced with `[redacted]`, including values for another origin the instance redirects to. Firecrawl redacts an error body before cutting it to 4096 bytes, so a value at the cut is no longer left half-visible. A header the request already sets is now recognised in any capitalisation and is no longer sent twice.

**`ketch doctor` now says when an auth proxy rejects an instance.** With `http_headers` configured for a self-hosted SearXNG, Firecrawl, Degoog, or Sourcegraph instance, a 401 or 403 now leads with `rejected (HTTP 403); http_headers are set for https://searx.example.com (Cf-Access-Client-Id, Cf-Access-Client-Secret), check they are current`, followed by the backend's own advice about its JSON format or API key, which used to be all it said. A redirect to another origin, such as an Access login page, is named as one by every backend, even when it ends at a working instance, since the headers never reach it there. When several Firecrawl keys fail the same way, the advice is printed once for all of them. Sourcegraph, whose check used to pass on a 401 or 403, now fails it in that case. Header names are shown, never values, and doctor output is unchanged for instances with no `http_headers`.

### Added

Google results through the [Serply](https://serply.io) REST API: `GET https://api.serply.io/v1/search/?q=&num=` with the key in the `X-Api-Key` header, never a query param. Keyed only, via `serply_api_key` / `serply_api_keys` / `KETCH_SERPLY_API_KEY`. The response's `results` array maps `title`/`link`/`description` onto ketch's standard result fields. ### Changed
- **Web search works with no configuration.** The default backend is now `auto`, a fallback chain instead of a single provider, so `brew install ketch && ketch search "query"` returns results without an API key. `auto` tries providers in a fixed order and returns the first that answers: an operator's own instances first (`searxng` once `searxng_url` points somewhere other than the built-in localhost default, then `degoog`), then any provider with an explicitly configured key, then the keyless hosted providers (`parallel` → `exa` → `keenable` → `youcom` → `firecrawl` → `ddg`). DuckDuckGo is last because ketch scrapes its HTML interface, the most rate-limited path of the set.

  Existing installs are unaffected: an explicit `backend` in config still wins, and because a configured key promotes its provider to the front of the chain, someone who set `brave_api_key` without ever setting `backend` keeps searching Brave. Setting a key remains how you pick a provider and lift the keyless caps — it no longer also requires setting `backend`.

  Each attempt is bounded at 10s and the whole chain at 30s; if every provider fails the error names each one and the exit code is `4` (upstream). The `backend:` output field and the MCP `backend` field report the provider that actually served rather than `auto`, with providers that failed on the way reported on stderr (CLI) or in the additive `errors` map (MCP). `ketch doctor` gains an `auto` row summarising the chain, healthy when any member answers and derived from the per-provider probes rather than re-probing them. `auto` is rejected inside `--multi` / `--random`, which already select backends, and is never part of their `=all` expansion.

  New search providers join the chain by setting `AutoRank` on their registry descriptor — zero keeps a provider out, lower non-zero ranks are tried first — so the chain follows the provider registry like every other shared consumer.
- **Homebrew install moved to homebrew-core**: install with `brew install ketch`. Releases no longer publish to the `1broseidon/tap` tap; its `ketch` formula was removed and a tap migration moves existing tap installs to `homebrew/core` on the next `brew update`.

### Fixed
- **Exa reported upstream failures as empty successes.** The MCP response decoder read only `result.content`, so a JSON-RPC `error` object or a tool-level `isError` (both served under HTTP 200) unmarshalled into zero results and no error, and a tool error's message was parsed as if it were search output. Exa now checks both error shapes like the Parallel and You.com decoders do. This mattered more with the `auto` chain: a failure disguised as an empty result set is indistinguishable from a query that genuinely matched nothing, so it would stop the chain from falling through to the next provider.
- `--minimal` output keeps one result per line. Titles, descriptions, and snippets are flattened to a single line with tabs collapsed, so a multi-line description from a provider no longer splits a result across lines or shifts its columns (`search`, including `--multi`, `--random`, and `--scrape`; `code`; `docs`).
- `serpbase` search works against the current SerpBase API (#58). The provider now requires `POST /google/search` with the key in the `X-API-Key` header and a JSON body (`q`/`hl`/`gl`/`page`); the old GET request returned `405 Method Not Allowed`. The response's `organic` array and business `status` field are decoded — the gateway reports errors with HTTP 200, so `1001` (invalid key), `1020` (credits exhausted), and `1029` (rate limited) are read from the body, and key rotation triggers on `1001`/`1029` (plus HTTP `401`/`403`/`429`). `ketch doctor`'s probe uses the same request and classification. The API exposes no page-size parameter and returns about ten organic results per page, so `--limit` above ten still yields a single page.

- Parallel search results no longer break the one-result-per-line output contract. Parallel returns extracted page text, so titles and excerpts can carry newlines, tabs, and indentation; bounding the description by rune count capped its length but not its shape, and titles were passed through raw. Because results print one per line — `--minimal` emits `url\ttitle\tdescription\n` — an embedded newline split a single result across many lines (a 3-result query emitted 30 lines) and corrupted row parsing for scripted callers. Both fields now collapse runs of whitespace to a single space before bounding; `Content` still keeps the complete, unflattened excerpt text. Scoped to the Parallel backend — other providers return short single-line snippets natively.
- `ketch doctor` no longer reports healthy self-hosted search instances as `unreachable`. Both offenders answer more slowly than a hosted API because they run the search themselves: self-hosted Firecrawl spends about eight seconds on a one-result query, and SearXNG about three — landing exactly on doctor's 3s per-probe budget. A self-hosted Firecrawl is now probed for liveness instead of results (a request its validation rejects still proves `/v2/search` answers, distinguishes a base URL pointing elsewhere via 404, and surfaces an instance that demands a key), which also drops that check from a timeout to milliseconds. SearXNG keeps its real `format=json` search — that probe is what detects the blocked-JSON trap — on a 10s budget. Wrong-base 404s now name `firecrawl_url` in the fix hint.

### Changed
- Contributor-facing design documentation now lives in `design/`: `DESIGN.md` (the mental model, core abstractions, and the reasoning behind each design principle, including an explicit Non-Goals & Scope section), `ROADMAP.md` (non-committal, dependency-ordered directions), and `adr/` (Architecture Decision Records, including new records for the exit-code/error-prefix taxonomy and fast-path-first scraping). Previously the ADR directory sat inside `docs/`, which is the Go package `github.com/1broseidon/ketch/docs`; the prose has moved out so that directory holds only package source.

## [0.13.0] - 2026-07-25

### Added
- **Environment-variable configuration** (#26). Nearly every config key now has a `KETCH_*` env override (mechanical `KETCH_` + upper-snake naming, e.g. `KETCH_BRAVE_API_KEY`, `KETCH_LIMIT`), with precedence CLI flag > env > config file > default. Override via `ketch config set user_agent <ua>`, `KETCH_USER_AGENT`, or `--user-agent` on `scrape` / `search` / `crawl` (flag > env > config > default). Empty clears back to the built-in default. `ketch config` always reports the effective UA so agents can diagnose bot-filter 403s without guessing.

### Changed
- Default scrape `User-Agent` is now an honest `ketch/<version> (+https://github.com/1broseidon/ketch)` instead of `Mozilla/5.0 (compatible; ketch/1.0)`. The old string matched Shield Security / similar fake-crawler rules (e.g. `https://jenson.org/ma/` returned HTTP 403 while bare `curl` succeeded). No browser impersonation — operators who need a custom UA set one explicitly. Release builds embed the semver; local/dirty builds collapse to `ketch/dev`.
- Headless browser fetches no longer inherit Rod's default `LaptopWithMDPIScreen` device emulation (a hardcoded macOS Chrome 114 UA that bot filters also blocklist). Cleared via `devices.Clear`, so the browser presents as the real installed Chrome, including `sec-ch-ua` client hints.

### Fixed
- Readability no longer silently drops data tables when a smaller table (e.g. a Wikipedia infobox) survives extraction (#28). The raw-table fallback now compares DOM data-table counts between the raw HTML and readability's output — ignoring layout/nav/footer/presentation/hidden tables — and only swaps to the noisier full-page conversion when readability actually lost tables. Relative links on the raw path are absolutized via `converter.WithDomain`, so recovered tables don't ship bare `/wiki/...` hrefs. Verified against `https://en.wikipedia.org/wiki/List_of_FIFA_World_Cup_finals`.
- `ketch browser install` no longer wedges after an interrupted download (#27). Extraction is not atomic, so a partial tree left by a cancelled or failed download broke every subsequent attempt — and broke it *differently* each time (`expected only one dir in ...` when the leftover confused the single-directory check, then `file exists` on the framework symlinks, which Rod reports as the misleading "can't find a browser binary for your OS"). - `--force-browser` no longer aborts when the preliminary HTTP classification probe is blocked (HTTP 403/etc.). Without a configured browser the probe error is still returned.

## [0.12.0] - 2026-07-15

### Added
- **BYO-cookie support** (#25) for session- and consent-gated pages (e.g. Nvidia NGC docs that render as a bare consent banner to an anonymous headless browser). ketch loads a **Netscape `cookies.txt`** jar — the format exported by browser cookies.txt extensions and consumed by `curl`/`yt-dlp` (no bespoke JSON schema) — via the new `cookies/` package, honoring the `#HttpOnly_` line prefix, rejecting malformed scope fields, and rechecking expiry before every request. Two ingestion surfaces feed one jar: a `--cookie-file <path>` flag on `scrape`, `search` (for `--scrape` fetches), and `crawl`, plus a persistent `ketch config set cookie_file <path>` key; the flag overrides config, and an explicit empty flag disables cookies for the run. Matching cookies are injected at **both** fetch layers — the HTTP request (including `/llms.txt`, sitemaps, and nested sitemap indexes) and the Rod browser path (cookies set before navigation, which is what unblocks consent-banner walls). HTTP redirects clear inherited cookies and re-match Domain, HostOnly, Path, and Secure scope for every hop, preventing HTTPS-to-HTTP, subdomain, and path-scope leaks. A short fingerprint of every live cookie in the configured jar is folded into the page-cache key, isolating the namespace even before a redirect reaches cookie scope, so authenticated content never collides with anonymous cached copies. Crawl inherits the same jar and cache-key behavior automatically. Cookie values are never printed anywhere (frontmatter, `--json`, errors, `doctor`): `ketch doctor` reports `cookies/jar: configured (N cookies, M expired)`, and a group/world-readable jar triggers a one-time stderr `chmod 600` warning. The cache directory/database use private `0700`/`0600` modes on POSIX and existing database permissions are tightened on open; authenticated responses remain cacheable under cookie-specific keys, so use `--no-cache` when they must not be stored. Non-goals: no password storage, no reading browser profile cookie DBs, no CDP attach to a running browser, no per-call MCP cookie parameter (config-level `cookie_file` still applies to MCP). Respecting site ToS and using only your own session cookies is the operator's responsibility.
- **Multiple API keys per provider** (#23). Plural config fields (`brave_api_keys`, `exa_api_keys`, `firecrawl_api_keys`, `keenable_api_keys`) alongside the existing singular fields; a random key is picked per request to spread rate limits. One retry on 401/429 (402 for Firecrawl) with a different key when the pool has more than one. Config set accepts JSON arrays; config show reports counts only; doctor probes effective key pools. Config file mode enforced to 0600; no key values in any output.
- **Random provider selection** (#24). `--random=brave,ddg,exa` shuffles providers, tries one, and falls back to the rest on failure — stops on the first successful response. Mirrors `--multi` flag semantics, mutually exclusive with `--backend`/`--multi`. MCP parity via `random` param. Output shows which backend answered and which failed.
- PDF text extraction for `scrape`, `search --scrape`, and `crawl` (#19). Text-based PDFs are detected by MIME type or `%PDF-` magic bytes and extracted by the always-available pure-Go `ledongthuc/pdf` implementation. Operators can instead configure `external_pdf_to_md_converter_command` (validated shlex syntax with exactly one `{input}` placeholder, Markdown on stdout capped at 10 MiB) and `external_pdf_to_md_converter_timeout_sec` (default 300 seconds); the external converter is authoritative and never silently falls back to the built-in parser. Response bodies retain the existing behavior of truncating at 20 MiB. `--raw` and `--select` reject PDFs as validation errors (exit 2 / `[validation]`); normal `--force-browser` PDF scrapes bypass Chromium and extract text directly. PDFs without a text layer are non-retryable precondition errors (exit 5 / `[precondition]`) with an OCR-converter hint. Crawl link discovery and browser rendering now run only for HTML responses.
- Renamed bundled skill verb `research.md` → `ketch-research.md` (#22) to avoid namespace conflicts for users who already have their own `research` skill installed.

### Changed
- The existing `scrape.NewBrowserConn(binPath string)` API remains source-compatible; `scrape.NewBrowserConnWithCookies(binPath string, jar *cookies.Jar)` adds cookie-aware browser construction. The `BrowserConn` interface itself is unchanged. Page-cache keys are now cookie-aware: a configured jar with live cookies gets an isolated namespace, including when only a redirect target matches.

## [0.11.0] - 2026-07-07

### Added
- **Federated multi-backend search** via `ketch search --multi` (and the MCP `search` tool's `multi` input): query several backends at once and fuse their rankings with [Reciprocal Rank Fusion](https://doi.org/10.1145/1571941.1572114) (RRF, k=60) so a page multiple engines rank highly rises to the top — better results, not just more. Bare `--multi` (or `--multi=all`) federates every *usable* backend using the same key-presence rule as the rest of ketch (`ddg`/`exa`/`keenable` always; `brave`/`firecrawl` with a key; `searxng` always, a dead instance just fails fast and is skipped), so a zero-config install still gets a real federation. `--multi=brave,exa` picks an explicit ordered set — an unknown name is a validation error (exit 2 / `[validation]`), a named-but-unconfigured backend a precondition error (exit 5 / `[precondition]`). Mutually exclusive with `--backend` (a set contradiction is rejected loudly, not silently resolved). Because `--multi` takes an optional value, a list needs the `=` form (`--multi=brave,exa`); `--multi brave,exa` is caught and rejected as a validation error with a hint to use `--multi=brave,exa`. Results are deduplicated by a new order-of-operations URL canonicalization (scheme/host lowercasing, `http`→`https` folding, default-port and `www.`/fragment/tracking-param stripping — canonical form is a merge key only, so the emitted URL is always an original backend URL). Each backend is fanned out concurrently with a 10s per-backend timeout; backends that error or time out are dropped and reported (CLI: `warn:` on stderr plus a `failed:` frontmatter key; MCP: an additive `errors` map), and the search only fails (`[upstream]` / exit 4) when every backend fails. Output is additive: `search.Result` gains a `backends` field (omitted for single-backend runs, so existing output is byte-identical), the plain-text frontmatter uses `backends:`/`failed:` with a per-result `found in:` line, and `--minimal` appends a 4th backends column under `--multi`. No result caching in v1 (a `--multi` query costs N live searches, exactly like N single searches today). Also refreshes the MCP `search` tool description, which had drifted to enumerate only four of the six backends.
- `firecrawl` web search backend via the [Firecrawl](https://docs.firecrawl.dev) v2 search API (`POST /v2/search`), configured with `ketch config set firecrawl_api_key <key>` and selected with `ketch config set backend firecrawl` or `ketch search -b firecrawl`. Uses the shared `httpx` client and slots into the existing `search.Searcher` interface / `NewFromConfig` switch like the other backends. `ketch config` discovery reports `firecrawl_api_key_set`, and `ketch doctor` gains a live search-backend probe (`ok` / `no_key` / `misconfigured` / `unreachable`). Same provider that powers Firecrawl scrape/crawl workflows, for operators who want one key for both search and page extraction.
- `keenable` web search backend over the Keenable index, built for AI agents. Keyless by default (public endpoint, rate-limited); an optional `keenable_api_key` lifts the rate limit. Wired into `ketch doctor` as a keyless reachability probe.
- `ketch extract` — a stdin-only Cobra subcommand that runs ketch's readability + HTML-to-markdown pipeline over piped HTML and emits frontmatter + markdown (or JSON via the root `--json`). Reads raw HTML from stdin (`curl -L https://example.com | ketch extract`, `cat page.html | ketch extract --select main`), rejects positional args and non-piped terminals with `ExitValidation`, and supports `--url` (metadata + relative-link resolution only; never printed as `about:blank`), `--select` (CSS selector path, exit 3 on no match, exit 2 on a bad selector), `--trim`, and `--max-chars`. Deliberately CLI-only and fetch-free: no cache, no `/llms.txt` probe, no browser rendering, no concurrency, and none of scrape's `--raw`/`--no-cache`/`--concurrency`/`--force-browser`/`--no-llms-txt` flags. The MCP tool surface is unchanged — `extract` is not exposed as a tool.
- Claude Code plugin + marketplace manifest: the repo now doubles as a Claude Code plugin marketplace (`.claude-plugin/marketplace.json`) hosting one plugin (`plugins/ketch/`) — `claude plugin marketplace add 1broseidon/ketch`, then `claude plugin install ketch@ketch`. The plugin is an optional convenience for Claude Code users, never a prerequisite (the stateless CLI remains the zero-infrastructure path): it wires up `ketch mcp serve` as a stdio MCP server (`.mcp.json`, expects the ketch binary >= v0.10.0 on PATH — the plugin does not vendor it) and ships the bundled agent skill via a symlink to the canonical copy at [`skills/ketch/`](./skills/ketch/), which stays where it is for non-Claude-Code agents.

Rules validated at `ketch config set url_rewrites '<json>'` time (JSON parse + regex compile); first-match-wins; capture groups (`$1`, `$2`) supported in `replace`. Closes #9.

### Changed
- `crawl.Crawl()` signature now takes `*scrape.Scraper` from the caller (was constructed internally from `Options.BrowserBin`); `Options.BrowserBin` removed. Only affects direct importers of the `crawl` package — the `ketch crawl` CLI is unchanged. Lets the cmd-layer `newScraper()` helper own scraper construction uniformly across `scrape`, `search`, and `crawl`.

### Fixed
- Broken example URLs in README (#8, thanks @abhmul).

## [0.7.0] - 2026-04-21

### Added
- `ketch version` command and `--version` flag. Reports build version, commit, and date injected by goreleaser; falls back to `debug.ReadBuildInfo()` for `go install` builds.
- Passive update reminder: when a newer release exists, a two-line hint is printed to stderr after command output. Cached for 24h; throttled so the same version is only announced once per 24h. Honors `KETCH_NO_UPDATE_NOTIFIER=1`, `CI`, `--json`, and non-TTY stderr. Install-type detection selects the right upgrade command (homebrew / `go install` / release URL).
- Ctrl+C (SIGINT) and SIGTERM now cancel the root context, so foreground `ketch crawl` drains gracefully: workers stop, in-flight HTTP aborts, summary prints, exit 0. Previously the default signal handler hard-killed the process.

### Changed
- HTTP stack tuned for crawling: shared `*http.Transport` with a 30s request Timeout, `MaxIdleConnsPerHost=16`, HTTP/2, and a keep-alive dialer (new `internal/httpx`). Every backend (brave, ddg, searxng, context7, sourcegraph, github, scraper) reuses it. Measured: 50 requests to one host in ~385ms; 20 mixed-host URLs at c=10 in ~300ms (down from ~9.7s at c=1).
- `context.Context` is now plumbed through `Scraper.Scrape/Fetch/ScrapeConditional/BrowserScrape/MaybeBrowserFetch`, `BrowserConn.Fetch` (via rod `Page.Context(ctx)`), `crawl.Crawl`, `fetchSitemap`, and `fetchLLMSTxt`. Cancellation reaches all the way into rod and `http.Client.Do`.
- `crawl.Options.StopCh` removed — cancellation is via the ctx passed to `crawl.Crawl`. `ketch crawl stop <id>` sends SIGTERM, which cancels the worker ctx and aborts in-flight requests mid-fetch.
- `DetectJSShell` rewritten: single DOM traversal for the static-page fast path, lazy corroborator phase. `DetectJSShellFromDoc` accepts a pre-parsed document so callers don't pay twice. `ScrapeConditional` parses HTML once and exposes the `*goquery.Document` via `FetchResult.Doc`; the crawler reuses it for link extraction instead of re-parsing.
- Crawl scheduler replaced: `sync.Cond` + growing slice → `chan queueItem` + `sync.WaitGroup` with goroutine-per-enqueue. The old pop pattern (`queue = queue[1:]`) never reclaimed the backing array.
- All HTTP response bodies are capped at 20 MiB via `io.LimitReader` so a misbehaving server cannot OOM the process.
